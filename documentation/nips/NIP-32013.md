NIP-32013
=========
Delegate Trust
---------------------------

`draft` `optional` `author:Vision_DWoT` `author:Keutmann`

## Abstract

This NIP defines **delegate trust** events (kind `32013`) that **augment** graph-trust in another kind — **default** [NIP-32010](documentation/nips/NIP-32010.md) (t1). Kind `32013` carries **no** trust **`v`** value; **trust, neutral, and distrust** are expressed **only** on kind **`32010`** toward the delegate pubkey. A valid `32013` record means: when the same author’s latest kind-**`32010`** assertion to delegate **`p`** in context **`C`** has **`v` = `1`**, resolvers **MAY** treat traversal author → **`p`** as a **delegation** (e.g. **zero graph degree** for hop counting) instead of a normal trust edge. The replaceable **`d`** and required **`t`** tag share a leading segment **`K`**: the **augmented** Nostr kind this delegation applies to (**`32010`** today). **`d`** continues with delegate pubkey and context. Both author and delegate MUST sign when a delegation is recorded (**`sig`** tag). Revocation and compromise use **`32010`** **`v`** toward **`p`** only; a stale **`32013`** MUST **not** expand the graph if **`32010`** no longer has **`v` = `1`**.

## Motivation

[NIP-32010](documentation/nips/NIP-32010.md) carries **meaning** (`v`, subjects, context). A separate key may **stand in** for the author without an extra **degree** in path algorithms. **`32013`** records **dual consent** and **which** upstream trust kind is augmented — same wire shape for future “augment kind **`X`**” without a new Nostr kind per variant. **`32010`** remains the single place for **value**.

## Specification

### Delegate Trust Event (Kind `32013`)

Addressable event per [NIP-01](https://github.com/nostr-protocol/nips/blob/master/01.md). Kind `32013` is in the Nostr `30000`-`39999` range. **`d`** encodes **`K|P|C`**; **`t`** MUST equal **`K`**.

#### Format

*   **`kind`**: `32013`
*   **`content`**: **Required.** Human-readable reason for the delegation. MUST NOT exceed **1024 characters** (same as [NIP-32010](documentation/nips/NIP-32010.md)).
*   **`tags`**:
    *   `["d", "<K>|<delegate_pubkey_hex>|<context>"]`: **Required.** **Replaceable identifier.** **`K`** — ASCII decimal string of the **augmented** kind (MUST be **`32010`** for [NIP-32010](documentation/nips/NIP-32010.md) trust). **`P`** — delegate pubkey as **64 lowercase hex characters** (same encoding as the **`p`** tag and NIP-01 **`pubkey`** field — **not** raw binary). **ASCII `|`** (U+007C) between segments. **`C`** — UTF-8 context (MAY be empty for generic). **Parse:** match `^(\d+)\|([a-f0-9]{64})\|([\s\S]*)$` — group 1 = **`K`**, group 2 = **`P`**, group 3 = **`C`** (**`C` may contain `|`**). Same **`kind` `32013`**, author **`pubkey`**, and full **`d`** define one slot.
    *   `["t", "<K>"]`: **Required.** MUST equal **`K`** from **`d`**. Clients SHOULD use `kinds: [32013]` **and** `#t` (e.g. **`32010`**) when filtering augmentations for NIP-32010.
    *   `["p", "<delegate_pubkey_hex>"]`: **Required.** **64 lowercase hex characters** (ASCII text on the wire — **not** raw bytes). MUST exactly equal **`P`** from **`d`**.
    *   `["c", "<context>"]`: **Optional; at most one.** If present, MUST equal **`C`** from **`d`** byte-for-byte. If **omitted**, **`C` MUST be empty** and **`d`** ends with **`|…|`** after pubkey (trailing segment empty).
    *   `["sig", "<delegate_signature_hex>"]`: **Required** unless **`deletion`** is **`true`** (see **[Removing a kind `32013` event](#removing-a-kind-32013-event-from-circulation)**). BIP-340 signature by **`p`**; see **[Delegate signature](#delegate-signature-sig-tag)**.
    *   `["deletion", "true"]`: **Optional.** If present and equal to **`true`**, this event is a **tombstone** that revokes the delegation for this replaceable slot; **delegate `sig` MUST be omitted**. See **[Removing a kind `32013` event](#removing-a-kind-32013-event-from-circulation)**.

**Normative tag ordering:** **`d`** first; **`sig`** last when present; between: **`t`**, **`p`**, optional **`c`**, optional **`deletion`**.

There is **no** **`v`** tag on kind **`32013`**.

### Event id without `sig` (`id_without_sig`)

Let **`T`** be the event’s `tags`; **`T_minus_sig`** = **`T`** with all **`sig`** tags removed (order preserved).

`id_without_sig = lowercase_hex( SHA256( UTF8( JSON.stringify([0, pubkey, created_at, kind, T_minus_sig, content]) ) ) )`

per [NIP-01](https://github.com/nostr-protocol/nips/blob/master/01.md).

The published **`id`** includes **`sig`** in **`T`**, so **`id_without_sig` ≠ `id`** when **`sig`** is present.

### Delegate signature (`sig` tag)

`m = SHA256( UTF8( "nostr-delegation-trust-v1" + ":" + id_without_sig + ":" + P ) )`

ASCII and colons (U+003A); **`id_without_sig`** and **`P`** lowercase hex on the wire. **`sig`** tag: **128 lowercase hex** (64-byte Schnorr, Nostr style).

The delegate produces **`sig`** after **`id_without_sig`** is fixed, before the author signs the outer event.

### Signing and publishing (author)

**Active delegation (delegate must sign):**

1.  Choose **`K`**, **`P`**, **`C`**, **`content`**, **`created_at`**; set **`d = K + "|" + P + "|" + C`**; build **`t`**, **`p`**, optional **`c`** — **do not** set **`deletion`**.
2.  Compute **`id_without_sig`** (no **`sig`** in tags).
3.  Obtain delegate **`sig`** on **`m`**.
4.  Append **`["sig", sig_hex]`** last; verify; compute **`id`**; author signs.

**Tombstone (`deletion`):** Build tags including **`["deletion", "true"]`**; **omit** **`sig`**. Compute **`id`** (same as **`id_without_sig`**); author signs only.

### Verification

1.  **`kind` `32013`**; exactly one **`d`**, **`t`**, **`p`**; at most one **`c`**; at most one **`deletion`**; **`d`** first; **`sig`** last when present; **no** **`v`** tag.
2.  Parse **`K`**, **`P`**, **`C`** from **`d`**; **`t == K`**; **`p == P`**; **`c`** rules as in Format.
3.  If **`deletion`** is **`true`**: require **no** **`sig`** tag; skip delegate verification. Otherwise require exactly one **`sig`** and verify delegate signature (**`m`**, **`p`**).
4.  Verify author Nostr signature.

### When delegation applies (resolvers)

For author **A**, delegate **P**, context **C**, augmented kind **`K`** (e.g. **`32010`**):

1.  **Trust value** comes **only** from the latest valid kind-**`K`** trust event from **A** to subject **P** in context **C** ([NIP-32010](documentation/nips/NIP-32010.md) for **`K` = `32010`**).
2.  If that assertion has **`v` ≠ `1`**, **do not** apply **`32013`** for expansion (ignore any coexisting **`32013`** for that triple for graph-follow).
3.  If **`v` = `1`** **and** the latest valid **`32013`** from **A** for **`d`** = **`K|P|C`** passes **[Verification](#verification)** and is **not** a **`deletion`** tombstone (**`["deletion", "true"]`**), **delegation is active**: apply **[Augmentation vs kind `32010`](#augmentation-vs-kind-32010)**. If the latest event for that slot is a **`deletion`** tombstone, **do not** apply delegation augmentation ( **`32010`** **`v`** toward **`P`** is unchanged and still evaluated on its own).

### Augmentation vs kind `32010`

When delegation is **active** (previous section):

*   Resolvers MUST **not** treat the **A** → **P** kind-**`32010`** edge as a **separate** hop for **degree** counting; **MAY** use **zero** additional degree through **P** as a delegate (product policy).
*   **`32010`** still supplies **`v`** and all trust semantics; **`32013`** only flags **delegated** identity.

When **`v` = `0`** or **`v` = `-1`** on **`32010`**, the author revokes or distrusts **P** for **C**; **`32013`** MUST **not** override that.

### Removing a kind `32013` event from circulation

Trust semantics are still governed by [NIP-32010](documentation/nips/NIP-32010.md) **`v`** toward **`p`**; the following only concern **whether a `32013` object should still be considered published** by clients and relays.

**1. [NIP-09](https://github.com/nostr-protocol/nips/blob/master/09.md) — Event Deletion Request (kind `5`) — recommended**

The **author** (same **`pubkey`** as the **`32013`**) SHOULD publish a standard **kind `5`** deletion request per NIP-09:

*   **`e`** tags: each value is the **hex id** of a **`32013`** event to delete.
*   Optionally **`a`** tags for **addressable** coordinates, e.g. **`["a", "32013:<author_hex>:<d_value>"]`** (same **`d`** string as the delegate event), if the client/relay supports addressable deletion for that slot.

Relays and clients that honor NIP-09 SHOULD stop serving or displaying the targeted **`32013`** like any other deleted event. Deletion is **best-effort** on a decentralized network; some caches may retain old events.

**2. Tombstone via `deletion` tag — optional**

The **author** MAY publish a new kind **`32013`** in the **same** replaceable **`d`** slot (same **`kind`**, author **`pubkey`**, **`d`**) that includes:

`["deletion", "true"]`

When **`deletion`** is present and its value is the string **`true`** (case-sensitive), clients MUST treat this revision as **revoking** the delegation **record** for that slot: **no** active delegation from this event, regardless of other tags. **`content`** MAY be empty or a short reason.

For a **`deletion`** tombstone, the **`sig`** tag (delegate signature) **MAY be omitted** — only the **author**’s normal event signature is required — so the author can withdraw the delegation even if the delegate key is unavailable or hostile.

If **`deletion`** is **`true`**, verifiers MUST NOT require a delegate **`sig`**; if **`deletion`** is absent or not **`true`**, existing rules apply (**`sig`** required).

### Relationship to other NIPs

*   [NIP-32010](documentation/nips/NIP-32010.md) — **t1** directed graph trust; **`d`** without kind prefix.
*   [NIP-32011](documentation/nips/NIP-32011.md) / [NIP-32012](documentation/nips/NIP-32012.md) — index/bloom; **`t`** / first **`d`** segment **`32010`** refers to **indexed** trust events, not the trust event's own **`d`** shape.

## Client behavior (recommendation)

1.  Ingest **`32013`** with **`#t`** as needed (e.g. **`32010`**).
2.  Resolve latest **`32013`** per **`d`** slot; pair with latest **`32010`** **A→P** in **C**.
3.  Apply zero-degree (or similar) rule only when **both** valid **`32013`** and **`v` = `1`** on **`32010`**.
4.  After **`v`** drops on **`32010`**, ignore stale **`32013`** for graph expansion.
5.  To drop a **`32013`** from indexes/UI, prefer **[NIP-09](https://github.com/nostr-protocol/nips/blob/master/09.md)** kind **`5`**; optionally accept **`deletion`** **`true`** tombstones in the same **`d`** slot.

```json
{
  "kind": 32013,
  "pubkey": "<64 lowercase hex chars — event author; NIP-01>",
  "created_at": 1738368000,
  "content": "Work laptop key may act for me in development until I revoke trust on 32010.",
  "tags": [
    ["d", "32010|<64 lowercase hex — same string as p tag>|development"],
    ["t", "32010"],
    ["p", "<64 lowercase hex — delegate pubkey>"],
    ["c", "development"],
    ["sig", "<128-char lowercase hex: delegate schnorr signature>"]
  ],
  "sig": "<author event signature>"
}
```

(Generic context: **`["d", "32010|<64 lowercase hex — delegate>|"]`**, omit **`c`**.)

```json
    ["d", "32010|<64 lowercase hex — former delegate>|development"],

    ["p", "<64 lowercase hex — former delegate>"],
    ["c", "development"],
    ["deletion", "true"]
  ],
  "sig": "<author event signature only>"
}
```

## Security considerations

*   **Dual signature:** Invalid or missing delegate **`sig`** ⇒ reject.
*   **No `v` on `32013`:** Compromise and revocation are public on **`32010`**; resolvers MUST gate delegation on **`v` = `1`**.
*   **`d` / `t` / `p` / `c`:** Reject mismatches.
*   **Ordering:** Wrong tag order breaks **`id_without_sig`** verification (unless **`deletion`** tombstone omits **`sig`** — then only author signature applies).
*   **Deletion:** NIP-09 is not enforceable network-wide; **`deletion`** tombstones rely on clients replacing the latest replaceable per slot.
