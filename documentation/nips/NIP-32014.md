NIP-32014
=========
Subject Rating
---------------------------

`draft` `optional` `author:Vision_DWoT` `author:Keutmann`

## Abstract

This NIP defines **subject rating** events (kind `32014`). An author publishes a **numeric score** (default scale **0–100**) about a **subject** (identity, event, content, or external id — same subject model as [NIP-32010](documentation/nips/NIP-32010.md)) in an optional **context**. Ratings are **subjective attributes** for display, analytics, or downstream reputation — **not** trust-graph hops. Clients **MUST NOT** use kind **`32014`** to **expand** [NIP-32010](documentation/nips/NIP-32010.md) **t1** path traversal from the subject; that remains exclusive to kind **`32010`**. There is **no** **`t`** tag: these events **annotate the subject** directly; **`t`** is reserved for kinds that **index or augment** another kind (e.g. [NIP-32011](documentation/nips/NIP-32011.md) / [NIP-32012](documentation/nips/NIP-32012.md) / [NIP-32013](documentation/nips/NIP-32013.md)). Discovery uses **`kinds: [32014]`** (and **`#d`** / subject filters as needed).

## Motivation

[NIP-32010](documentation/nips/NIP-32010.md) uses a coarse **`v`** (−1 / 0 / 1) for **graph trust**. Many use cases need a **graded** score (quality, risk, satisfaction) without implying “follow this edge in the web-of-trust.” A dedicated **rating** kind keeps tri-state **trust** and **fine-grained scores** separate and composable.

## Specification

### Rating Event (Kind `32014`)

Kind **`32014`** is a **Parameterized Replaceable Event** per [NIP-01](https://github.com/nostr-protocol/nips/blob/master/01.md). **One subject per event** (no batch in this NIP). The replaceable **`d`** value uses the same **`d_base[|context]`** derivation as [NIP-32010](documentation/nips/NIP-32010.md) for that single subject; the replaceable **slot** is distinct because **`kind`** differs from **`32010`**.

#### Format

*   **`kind`**: `32014`
*   **`content`**: Optional. Human-readable note. SHOULD NOT exceed **1024 characters**.
*   **`tags`**:
    *   `["d", "<d_base>[|context]"]`: **Required.** Same **`d_base`** and optional **`|context`** rules as [NIP-32010](documentation/nips/NIP-32010.md) [`d` tag derivation](documentation/nips/NIP-32010.md#d-tag-derivation-replaceable-identifier) for **one** subject tag (see Subject tags below).
    *   `["score", "<integer>"]`: **Required.** The rating value. Default scale: **inclusive integers `0` through `100`**. Leading zeros SHOULD NOT be used. An **empty string** value (`["score", ""]`) is a **tombstone**: clients **MUST** treat the replaceable slot as **cleared** — the rating is **not** present in resolved state (see [Tombstone (empty score)](#tombstone-empty-score)).
    *   `["scale", "<min>-<max>"]`: **Optional.** Declares the inclusive integer range, e.g. **`0-100`** (default when omitted). Other ranges MUST be positive integers with **`min ≤ max`**; clients that do not support a given scale MAY ignore the event or map values conservatively.
    *   `["c", "<context>"]`: **Optional; at most one.** Same semantics as [NIP-32010](documentation/nips/NIP-32010.md). If present for contextual ratings, MUST match the context segment in **`d`** when **`d`** includes **`|context`**. If omitted, **`d`** has **no** context segment (generic rating for that subject).
    *   `["x", "<unix_timestamp>"]`: **Optional; at most one.** **Activate** — Unix timestamp (seconds). The rating is valid for display/resolution only when the current time is **≥** this value. Same semantics as [NIP-32010](documentation/nips/NIP-32010.md) **`x`**. Omit if the rating applies immediately.
    *   `["y", "<unix_timestamp>"]`: **Optional; at most one.** **Expire** — Unix timestamp (seconds). The rating is valid for display/resolution only when the current time is **≤** this value. Same semantics as [NIP-32010](documentation/nips/NIP-32010.md) **`y`**. Omit if the rating does not expire.
    *   **Subject tags (exactly one required):** One of **`p`**, **`e`**, **`a`**, **`h`**, **`r`**, **`i`** (with **`k`** for **`i`** per NIP-32010 / NIP-73), with the **same** canonical values and preimage rules as NIP-32010 for **`d`** computation.

**Normative tag ordering:** **`d`** first, then **`score`**, optional **`scale`**, optional **`c`**, optional **`x`**, optional **`y`**, then the **single** subject tag (and **`k`** if **`i`** subject).

#### Tombstone (empty score)

Publishing a replaceable update whose **`score`** value is the **empty string** clears that author’s **`32014`** slot for the same **`d`**. Clients resolving ratings **MUST** omit that slot from the **attribute** (same **`d`**) as if no rating were published — i.e. it is **removed from the resolved graph** of subject attributes.

#### Verification

1.  Exactly **one** subject tag from the allowed set; **`d`** MUST match NIP-32010 derivation for that subject and context.
2.  If **`score`** is **not** empty: **`score`** MUST parse as an integer in **`[min, max]`** from **`scale`** (default **`0`**–**`100`**). If **`score`** is empty, the event is a **tombstone**; do **not** apply numeric validation to **`score`**.
3.  If **`x`** and/or **`y`** are present, each value MUST parse as a non-negative integer (Unix seconds). If **both** are present, **`x`** SHOULD be **≤** **`y`** (otherwise the validity window is empty).

## Relationship to NIP-32010

*   **Trust (`32010`)** — path algorithm **may** traverse positive trust edges (**t1**).
*   **Rating (`32014`)** — **never** a traversal edge; **may** be shown beside subjects or fed into separate reputation models.

Publishing both a trust event and a rating for the same subject is allowed; they mean different things.

## Client behavior (recommendation)

1.  Display ratings as **author-scoped** scores, not global truth.
2.  **Do not** add kind **`32014`** to trust-graph frontier expansion.
3.  **Validity window:** Treat the rating as current only when the wall-clock time satisfies **`x`** (if present: now **≥** **`x`**) and **`y`** (if present: now **≤** **`y`**), consistent with [NIP-32010](documentation/nips/NIP-32010.md) time rules. Events without **`x`** or **`y`** impose no bound on that side. **Tombstones** (**empty** **`score`**) have **no** effective rating regardless of **`x`**/**`y`**.
4.  **Latest wins** per replaceable slot (same author, kind **`32014`**, same **`d`**). If the latest event has an **empty** **`score`**, the slot contributes **nothing** to resolved subject attributes.

```json
{
  "kind": 32014,
  "pubkey": "<64 lowercase hex chars — author; NIP-01>",
  "created_at": 1738368000,
  "content": "After collaboration on the migration project.",
  "tags": [
    ["d", "<64 lowercase hex — same derivation as NIP-32010 for this p>|development"],
    ["score", "87"],
    ["c", "development"],
    ["p", "<64 lowercase hex — subject pubkey>"]
  ],
  "sig": "<author signature>"
}
```

```json
    ["scale", "0-100"],
    ["c", "sprint_review"],
```

```json
  ],
  "sig": "<author signature>"
}
```

## Security considerations

*   **Manipulation:** Numeric scores are cheap to publish; downstream systems SHOULD NOT treat them as Sybil-resistant without aggregation policy.
*   **Scale:** Mis-matched **`scale`** and **`score`** SHOULD be rejected by strict clients.
