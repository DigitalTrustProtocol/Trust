NIP-32016
=========
Subject Link
---------------------------

`draft` `optional` `author:Vision_DWoT` `author:Keutmann`

## Abstract

This NIP defines **subject link** events (kind `32016`). An author **binds** a **source** — typically a **URL** (social profile, website, repo) or an [NIP-73](https://github.com/nostr-protocol/nips/blob/master/73.md) **external identifier** — to a **Nostr-facing subject** (usually a **`p`** pubkey, but other subject types are allowed). Links are **attributed claims** (“I associate this URL with this key”), **not** proof of ownership and **not** trust-graph edges. The replaceable **`d`** tag is **only** the **64-character hex binding id** and optional **`|context`** — it does **not** embed the event kind or the subject. The **subject** comes **only** from the subject tag on the event; **`u`**, **`i`**, and **`k`** are the **link resource** used with that subject to form the binding. Clients **MUST NOT** use kind **`32016`** to **expand** [NIP-32010](documentation/nips/NIP-32010.md) **t1** path traversal from the subject. There is **no** **`t`** tag: these events **annotate the subject** directly; **`t`** is reserved for kinds that **index or augment** another kind (e.g. [NIP-32011](documentation/nips/NIP-32011.md) / [NIP-32012](documentation/nips/NIP-32012.md) / [NIP-32013](documentation/nips/NIP-32013.md)). Discovery uses **`kinds: [32016]`** (and **`#d`** / subject filters as needed).

## Motivation

Users often want to document **off-network** identities tied to **npubs** (e.g. a Facebook profile, a company page, a GitHub org). A dedicated **link** kind keeps these bindings separate from **trust** and **ratings**, while allowing clients to render **profile enrichment** or **disambiguation** without treating every link as a hop in the web-of-trust.

## Specification

### Link Event (Kind `32016`)

Kind **`32016`** is a **Parameterized Replaceable Event** per [NIP-01](https://github.com/nostr-protocol/nips/blob/master/01.md). Each event asserts **one** binding: **exactly one primary subject** + **one source** (URL and/or NIP-73 id). **Multiple** subject tags (**`p`**, **`e`**, etc.) on the same event are **forbidden** (except none when **`deletion`** is **`true`** on a minimal tombstone).

#### d tag (replaceable identifier)

The event **`kind`** is **`32016`**; **`d`** **MUST NOT** include the kind number or any subject material. It contains **only** the cryptographic **binding id** and optional **context**.

**Shape (pipe **`|`** is ASCII **`0x7C`**):**

`d = <binding_id>[|<context>]`

*   **`<binding_id>`** — **Required.** **64 lowercase hex** characters = `SHA256(UTF8(subject_canonical + "\x1e" + source_canonical))` — **0x1E** (record separator) between the two UTF-8 strings:
    *   **`subject_canonical`**: Derived from the **single** primary subject tag (**`p`** / **`e`** / **`a`** / **`h`** / **`r`** / **`i`**, with **`k`** paired to **`i`** per [NIP-32010](documentation/nips/NIP-32010.md) / NIP-73) using the same preimage rules as NIP-32010.
    *   **`source_canonical`**: Derived **only** from the **link resource** tags — **`u`**, **`i`**, **`k`** — per **Link resource** under [Format](#format) below (not from **`c`**, **`x`**, **`y`**, or **`deletion`**).
*   **`<context>`** — **Optional.** Same UTF-8 string as **`c`** when used. **MUST NOT** contain **`|`**. If omitted, **`d`** is **only** the 64 hex characters (no trailing **`|`**).

**Subject vs link resource:** Implementations **MUST** take **exactly one** tag among **`p`**, **`e`**, **`a`**, **`h`**, **`r`**, **`i`** as the **subject** (plus **`k`** when required for that **`i`**). That subject tag is **not** encoded in **`d`**; it is read from the event. **Link resource** tags — **`u`**, **`i`**, **`k`** — supply the off-network side of the binding and **MUST** be used to compute **`source_canonical`**. Tags **`d`**, **`c`**, **`x`**, **`y`**, **`deletion`** are **metadata** and **MUST NOT** be mixed into **`source_canonical`**. Relays and clients **SHOULD** index **`#p`** / **`#e`** / etc. from the subject tag; **`#d`** carries **only** **`binding_id[|context]`** for the replaceable slot.

#### Format

*   **`kind`**: `32016`
*   **`content`**: Optional. Why this binding exists; disclaimers (“not verified”). SHOULD NOT exceed **1024 characters**.
*   **`tags`**:
    *   `["d", "<calculated_id>"]`: **Required.** **Replaceable identifier** per [d tag (replaceable identifier)](#d-tag-replaceable-identifier) above.
    *   **Primary subject (exactly one, unless deleting):** one of **`p`**, **`e`**, **`a`**, **`h`**, **`r`**, **`i`** — the Nostr or content **subject** being annotated (canonical hex/text per NIP-32010). Omit only when **`deletion`** is **`true`** (tombstone). **MUST NOT** include more than one subject-type tag.
    *   **Link resource (at least one required unless deleting):**
        *   `["u", "<url>"]`: **Optional (if `i` provides the source).** Canonical **HTTP(S) or other URL** string for the external resource (profile page, etc.). Normalization MUST be stable within the implementation.
        *   `["i", "<external_id>"]` + `["k", "<scheme>"]`: **Optional (if `u` alone is enough).** [NIP-73](https://github.com/nostr-protocol/nips/blob/master/73.md) external identifier for non-URL sources or supplementary ids.
    *   `["c", "<context>"]`: **Optional; at most one.** Scopes the **meaning** of the link (e.g. `"personal"`, `"employer"`). If present, MUST appear as the optional **`|context`** suffix on **`d`** (same UTF-8 string).
    *   `["x", "<unix_timestamp>"]`: **Optional; at most one.** **Activate** — Unix timestamp (seconds). The link assertion is valid for resolution only when the current time is **≥** this value. Same semantics as [NIP-32010](documentation/nips/NIP-32010.md) **`x`**. Omit if the link applies immediately.
    *   `["y", "<unix_timestamp>"]`: **Optional; at most one.** **Expire** — Unix timestamp (seconds). The link assertion is valid for resolution only when the current time is **≤** this value. Same semantics as [NIP-32010](documentation/nips/NIP-32010.md) **`y`**. Omit if the link does not expire.
    *   `["deletion", "true"]`: **Optional; at most one.** MUST be the lowercase string **`true`** when used. **Tombstone:** clients **MUST** treat the replaceable slot as **cleared** — the link is **not** present in resolved state (see [Tombstone (deletion)](#tombstone-deletion)).

**Requirement:** At least one of **`u`** or **`i`** MUST be present **unless** **`deletion`** is **`true`**. **Exactly one** primary subject tag is required **unless** **`deletion`** is **`true`** (minimal tombstones may omit subject and link resource; **`d`** identifies the slot). **`p`** is **RECOMMENDED** as the primary subject for profile-style links when not deleting.

**Normative tag ordering:** **`d`** first, optional **`c`**, optional **`x`**, optional **`y`**, optional **`deletion`**, primary subject tag (if any), then **`u`** and/or **`i`** / **`k`**.

#### Tombstone (deletion)

Publishing a replaceable update with **`["deletion", "true"]`** clears that author’s **`32016`** slot for the same **`d`**. Clients resolving links **MUST** omit that binding from subject attributes — **removed from the resolved graph**. **`d`** alone identifies the cleared slot; **publishers SHOULD** still include subject + link-resource tags when practical so **`d`** can be **verified** against recomputed **`binding_id`**.

#### Verification

1.  **Parse `d`:** Split **`d`** on **`|`** into **1** or **2** segments. Segment **0** MUST be **64 lowercase hex** (**`binding_id`**). Segment **1**, if present, is **`<context>`** and MUST match the **`c`** tag when **`c`** is present. **MUST NOT** use any other segment count.
2.  **Single subject on the wire:** The event MUST have **at most one** tag whose name is in **`p`**, **`e`**, **`a`**, **`h`**, **`r`**, **`i`** (no batch).
3.  If **`deletion`** is **not** **`true`**: exactly **one** primary subject tag; at least one link-resource tag (**`u`** and/or **`i`**). Recompute **`binding_id`** from **`subject_canonical`** + **`source_canonical`** (link resource only); it MUST equal segment **0** of **`d`**.
4.  If **`deletion`** is **`true`**: **`d`** MUST satisfy (1). If subject and link-resource tags are present, recomputed **`binding_id`** MUST equal segment **0**; if omitted, clients **MAY** accept the tombstone when **`d`** is well-formed.
5.  If **`x`** and/or **`y`** are present, each value MUST parse as a non-negative integer (Unix seconds). If **both** are present, **`x`** SHOULD be **≤** **`y`**.

## Relationship to other NIPs

*   [NIP-32010](documentation/nips/NIP-32010.md) — **Trust** (t1); links do **not** add trust edges.
*   [NIP-32014](documentation/nips/NIP-32014.md) / [NIP-32015](documentation/nips/NIP-32015.md) — Other **non-graph** subject attributes.

## Client behavior (recommendation)

1.  Display links as **“claimed by author”**, not verified ownership, unless verified by other means.
2.  **Do not** expand the trust graph through **`32016`** events.
3.  **Validity window:** Apply **`x`** / **`y`** like [NIP-32010](documentation/nips/NIP-32010.md) (now **≥** **`x`** if **`x`** present; now **≤** **`y`** if **`y`** present). **`deletion` `true`** clears the slot regardless of **`x`**/**`y`**.
4.  **Latest wins** per replaceable **`d`** slot. If the latest event has **`deletion` `true`**, the slot contributes **no** link to resolved subject attributes.

## Example JSON (URL to pubkey)

```json
{
  "kind": 32016,
  "pubkey": "<64 lowercase hex chars — author; NIP-01>",
  "created_at": 1738368000,
  "content": "My public Facebook page for friends who do not use Nostr.",
  "tags": [
    ["d", "<64 hex SHA256 binding_id>|personal"],
    ["c", "personal"],
    ["x", "1672531200"],
    ["y", "1704067200"],
    ["p", "<64 lowercase hex — my pubkey>"],
    ["u", "https://facebook.com/example.profile"]
  ],
  "sig": "<author signature>"
}
```

(Optional **`x`** / **`y`** bound when the link assertion applies; omit either side for no bound on that side.)

#### Example JSON (tombstone — clear slot)

```json
{
  "kind": 32016,
  "pubkey": "<64 lowercase hex chars — author; NIP-01>",
  "created_at": 1738444400,
  "content": "",
  "tags": [
    ["d", "<same 64-hex binding_id as the link being removed>|personal"],
    ["deletion", "true"]
  ],
  "sig": "<author signature>"
}
```

## Security considerations

*   **Impersonation:** Anyone can link any URL to any pubkey; **downstream MUST NOT** treat **`32016`** as proof of control of the URL.
*   **Phishing:** Clients SHOULD warn when opening external **`u`** values.
